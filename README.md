# Search or Sample? Budgeting Symbolic Regression

This repository reproduces an experimental study of choosing between more evolutionary search and another labeled observation. The **Split** controller compares corrected bootstrap sensitivity with residual search variation using a nested committee. Every policy uses the same tree-based genetic-programming engine and an explicit budget for search blocks and labels.

## Contents

- `sos/`: deterministic seeded evolutionary search, synthetic targets, engineering-data loading, and allocation policies.
- `configs/`: complete development, main, acquisition-control, engineering, and sensitivity configurations.
- `data/`: Airfoil Self-Noise and Concrete Compressive Strength data, with provenance and checksums.
- `results/`: saved per-run models, acquired indices, performance trajectories, and calibration/action-audit outcomes.
- `analysis/`: numerical summaries and the development-selected fixed schedules.
- `MANIFEST.json` and `verify_integrity.py`: SHA-256 integrity verification of the released files.
- `tests/`: checks of arithmetic, protected division, acquired-label isolation, tree variation, allocation, and repeatability.
- `reproduce.py`: complete experiment execution and numerical analysis.
- `verify_reproduction.py`: reruns representative saved experiments and checks scientific outputs.
- `calibrate_diagnostic.py`: Monte Carlo verification of the idealized variance-component calculation.
- `audit_actions.py`: paired equal-cost search, acquisition, and bootstrap-refresh branches from cloned states.
- `benchmark_hardware.py`: optional compiled-CPU versus Metal-GPU evaluation benchmark.

## Reference findings

Across the controlled equations, Split has 2.50 times the geometric mean prediction error of the fixed acquisition schedule selected on separate development tasks. The difference is concentrated in noisy observations. In the 720-state equal-cost audit, the gate selects acquisition in 5.4% of states, while acquisition has lower measured continuation risk in 59.3%. Its balanced action accuracy outside practical ties is 0.509. These findings distinguish a decomposition of committee variability from prediction of the benefit of an action. The complete policy comparisons and uncertainty intervals are regenerated by `analyze_results.py`.

## Installation

Run the commands below from the top-level repository directory.

The recorded environment is Python 3.12.1 on an Apple M3 Pro with 18 GB unified memory. The core experiments use compiled CPU kernels and independent worker processes. Python 3.12 and the pinned packages provide the reference environment.

```bash
python3.12 verify_integrity.py
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

For the optional Metal benchmark, install `requirements-metal.txt` and run `python benchmark_hardware.py`. GPU availability is detected automatically. The benchmark measures the supplied evaluators; its result depends on batch size, precision, and implementation.

## Recompute numerical summaries

```bash
python analyze_results.py --results results --out analysis
```

This reads the included saved runs, checks expected counts, selects fixed baselines using development data only, and regenerates CSV and JSON summaries. Ratios compare paired runs; across-equation intervals use 10,000 equation-cluster bootstrap replicates. Main-study geometric means use `NMSE + 1e-8`. Expanded-domain evaluation samples the larger cube, which includes both interior and exterior inputs. The recorded-checkpoint summary retains the actual mean expenditure at each stored checkpoint; checkpoint indices are not common budget values across policies.

## Repeat the experiments

```bash
python reproduce.py --workers 10 --out-root reproduced
```

The command creates a fresh result tree, runs development before main experiments, then evaluates engineering datasets, sensitivity configurations, idealized calibration, and counterfactual actions. Individual trials are resumed by their configuration hash when rerunning the same command. Worker count can be reduced to leave resources available for other applications. Numerical kernels use one thread per worker.

To run one configured study:

```bash
python run_experiments.py --config configs/main.json --workers 10 --out reproduced/results/main
python run_experiments.py --config configs/main_acquisition_controls.json --workers 10 --out reproduced/results/main
python run_experiments.py --config configs/main_resampling_control.json --workers 10 --out reproduced/results/main
```

The second command adds uniform and maximin acquisition controls; the third adds the bootstrap-refresh control. Engineering acquisition controls follow the same pattern. Complete execution contains 2,376 development runs, 17,280 main runs, 2,160 engineering runs, 1,280 sensitivity runs, and 240 audited trajectories with 720 cloned states. Each audit state has four paired future-randomness replicates of search, acquisition, and bootstrap-refresh branches. Calibration evaluates 20 independently generated settings of 250,000 nested arrays, with three prices applied to each setting.

For a smaller repeatability check:

```bash
python verify_reproduction.py --results results --limit 18 --out verification.json
```

This checks model arrays, acquired indices, recorded risks, and trajectories against 18 representative stored experiments and one complete three-branch audit trajectory. Timing fields are excluded from equality checks. The numerical tolerance is relative `1e-10` and absolute `1e-12`; floating-point libraries or platforms can change borderline evolutionary selections, so the supplied environment and saved models are the reference.

## Budget and policies

A search action costs one unit. A sample action obtains one response and performs a search block, costing `1 + query_cost`. Common initial labels, population evaluation, and two warm-up blocks are accounted for separately. Synthetic main runs have an incremental budget of 64 units; engineering runs have 96. An unaffordable acquisition becomes a search action when a full search unit remains.

For committee prediction `p[b,r,x]`, `W` is the average within-bootstrap restart variance, `C` is the variance of bootstrap-row means, `S = W/R`, and `D = max(C-S, 0)`. Split acquires when the mean of `D` divided by `1 + query_cost` exceeds mean `S`, selecting the input with largest `D`.

Controls include search only, bootstrap refresh without new labels, acquisition at every affordable step with committee/uniform/maximin selection, fixed acquisition rates of 25%, 50%, and 75%, an uncorrected gate, random acquisition under the Split gate, and corrected acquisition under a fixed 50% schedule. The development-selected fixed baseline is a derived comparison, selected separately for each observation price.

The component correction is a classical random-effects calculation. The operational signals describe variability of this fitting procedure. Their ability to predict beneficial actions is tested separately by the counterfactual audit. Engineering labels are retrospectively revealed from public datasets.

## Result format

A run file is named by the first 16 hexadecimal digits of the SHA-256 hash of its sorted JSON specification. It records:

- `spec` and `config`: task, seed, noise, price, policy, and engine settings;
- `final` and `trace`: error, labels, budget, evolutionary work, and elapsed time;
- `acquired_indices`: revealed candidate-pool rows;
- `model`: tree operators, constants, affine intercept, and affine scale.

In a trace, `data_signal` records the statistic used by the policy gate; Uncorrected records the between-bootstrap quantity `C`, while Split records the corrected quantity `D`.

Trees use complete binary heap storage. Operator codes are documented in `sos/engine.py`; inactive descendants are ignored by the expression semantics. Final models are selected from surviving candidates using acquired labels. Test labels are used exclusively for recorded evaluation.
